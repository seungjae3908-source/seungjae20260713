# 4시장 무상 과거 데이터 공급원·이용 범위 점검

- 작성일: 2026-10-11 (Asia/Seoul)
- 대상: `seungjae3908-source/seungjae20260713` / 기존 Draft PR #1534
- 중앙 허브: GitHub Issue #1102
- 범위: P0 공급원 확인 및 P1 수집 설계 근거

## 1. 판정과 작업 경계

**공식 무상·공개 공급원으로 실제 수집을 시작할 수 있다. 다만 4시장 전체 종목의 전 기간 원본 1분봉, 상장폐지·거래종료 이력, 당시 거래가능 상태와 회원 서비스 제공권까지 확보된 것은 아니다.**

이 문서는 공급원이 공개한 API·상품·약관을 조사한 결과와, 별도 코인 공급원 점검 작업이 전달한 제한된 실측을 구분한다. 문서 확인은 데이터 수집 완료 증명이 아니며, 소수 시점의 API 응답 성공은 전 기간·전 종목의 완전성 증명이 아니다.

- 기존 연구·재생·백테스트 엔진과 Draft PR #1534를 재사용한다.
- Replit 및 Replit Agent를 사용하지 않는다.
- Ready, Merge, Staging, Production 배포 및 실거래 활성화를 수행하지 않는다.
- 데이터 공급원 가입, 약관 수락, 결제, 키 신규 발급 또는 서버 시크릿 변경을 이 문서 작업에서 수행하지 않았다.
- 이 문서에는 원본 가격, 원본 CSV, 인증키 및 토큰을 포함하지 않는다.
- 국내주식·미국주식·코인현물은 매수 전용, 코인선물은 LONG·SHORT 연구 범위를 유지한다.

다음 값은 이번 공급원 조사로 승격하지 않는다.

```text
PROFITABILITY_PROVEN=false
OOSPassCount=0
trueMarketWideRecall=null
paperAdmissionAllowed=false
executionAuthority=NONE
```

선택 기간은 1일·1주·1개월·3개월·6개월·1년·3년·5년·10년 및 사용자 지정 기간을 지원하는 것이 목표다. 3년은 기간 제한이 아니다. 요청 기간의 자료가 부족하면 해당 구간을 `데이터 부족`으로 표시하며, 기회 0건 또는 수익률 0%로 바꾸지 않는다.

## 3. 국내주식 상세

### 3.1 KRX Open API: 장기 일봉과 과거 종목정보

공식 서비스 목록은 유가증권·코스닥 일별매매정보와 종목기본정보를 2010-01-04부터 제공한다고 명시한다. 코넥스는 2013-07-01부터다. 이는 국내 장기 일봉·종목정보 수집의 우선 경로다. 해당 목록에서 원본 1분봉 제공을 확인한 것은 아니다. [KRX-01]

인증키 발급 승인과 **원하는 개별 API 활용신청 승인**이 각각 필요하다. 키가 있다는 이유만으로 KOSPI·KOSDAQ·KONEX의 일별매매·종목기본정보 6개 서비스를 모두 조회할 수 있다고 판정하지 않는다. [KRX-02]

현행 공개 약관에서 확인한 조건은 다음과 같다. [KRX-03]

- 비상업적 목적 이용 및 제3자 정보 제공 제한.
- 결과 화면의 한국거래소 통계정보 출처 표시.
- 키당 일 10,000회 이하 요청.
- 이용기간 1년과 연장 절차.

따라서 내부 연구용 접근 승인과 관리자·회원에게 원천 데이터를 제공하는 서비스 권한은 따로 기록한다. 약관·상품의 존재만으로 현재 계정의 사용 승인을 인정하지 않는다.

KRX는 별도로 상장폐지종목 현황 화면을 제공한다. KOSPI·KOSDAQ·KONEX, 종목코드, 상장일, 폐지일, 폐지사유를 확인할 수 있는 공식 참조 경로다. **이번 조사에서는 이 화면과 같은 자료를 반환하는 승인된 대량 API나 완전한 파일을 확보하지 않았다.** 과거 종목기본정보와 이 자료를 실제 대조한 뒤 상장폐지 포함 여부를 판정해야 한다. [KRX-04]

### 3.2 금융위원회 공공데이터: 보조 일봉·종목정보

`금융위원회_주식시세정보`는 일자·종목 기준 OHLC·거래량·거래대금 등을 제공하는 무료 API다. 별도 `금융위원회_KRX상장종목정보`도 무료이며, 활용신청 및 인증키가 필요하다. 현재 상세 페이지에 표시된 개발계정 신청 가능 트래픽은 10,000건이다. [KR-01], [KR-02]

주식시세 페이지의 일반 메타데이터에는 `실시간`이라는 표현이 있지만, 구체적 설명은 **일 1회 갱신, 기준일의 다음 영업일 오후 1시 이후 공개**라고 명시한다. 수집기의 갱신 정책은 이 상세 설명을 따른다. 이번 공식 페이지 확인만으로 10년의 실제 조회 가능 범위를 확정하지 않는다. [KR-01]

두 API는 공공누리 4유형으로 표시된다. 특히 주식시세 상세 설명은 제3자 무단 제공·재배포 금지와 상업 목적 이용 시 KRX 구매 필요를 명시한다. 무상 조회가 가능한 것과 회원 앱에서 원천 데이터를 제공할 수 있는 것은 별개다. [KR-01], [KR-02]

### 3.3 KIS: 최근 분봉 확보 경로

한국투자증권 공식 예제는 다음 기능을 명시한다. [KR-03]

```text
API: /uapi/domestic-stock/v1/quotations/inquire-time-dailychartprice
TR: FHKST03010230
날짜: FID_INPUT_DATE_1
시각: FID_INPUT_HOUR_1
실전계좌 기준 한 번에 최대 120건
보관 범위: 서버에 남아 있는 자료, 최대 1년 분봉
```

최근 1년 범위의 보조 공급원으로 사용할 수 있지만, 3·5·10년 국내 전 종목 원본 분봉 확보의 해결책으로 표시하면 안 된다. 시장 구분 `J`, `NX`, `UN`은 각각 구분해 저장한다. KRX만의 일봉과 통합시장 분봉을 동일한 거래장소 데이터라고 취급하지 않는다.

인증 App Key·Secret과 토큰이 필요하다. 공식 API 인증키가 주문에도 사용될 수 있다는 이유로 연구 작업에 주문 호출 권한을 부여하지 않는다. 기존 자격 증명 확인과 시장데이터 조회 구현은 별도 절차로 검증하며, 이 조사에서 증권 계좌 개설·인증 설정·새 공급권 취득은 수행하지 않았다.

### 3.4 키움 REST: 기존 연결의 실제 보유 범위 검증

키움 공식 샘플은 `ka10080`, `/api/dostk/chart`, `tic_scope=1`, `base_dt=YYYYMMDD`, `cont-yn`·`next-key` 연속조회를 제공한다. 원본과 수정주가 여부도 구분해야 한다. 공식 API 목록에는 일봉 `ka10081`도 있다. [KR-04], [KR-05]

**공식 샘플의 `MAX_PAGES=10`은 예제 구현의 상한이다. 공급원 보관기간이나 공식 최대 페이지 수의 근거로 사용하지 않는다.** 실제 대상 종목·날짜로 연속조회하여 최초·최종 반환시각, 조회 종료 이유와 누락 구간을 기록해야 한다.

이번 공식 문서 조사에서 키움의 국내 전 종목 10년 원본 1분봉 보장을 확인하지 못했다. 특정 날짜 입력이 가능하거나 한 종목의 오래된 봉을 받았다고 전체 기간·전체 종목을 확보했다고 판정하지 않는다.

### 3.5 OpenDART: 공시·기업 식별의 보조 자료

`corpCode.xml`은 회사 고유번호, 회사명, 상장회사 종목코드, 최종변경일을 제공하며 발급된 API 인증키가 필요하다. 기업행위·공시 자료의 연결에 사용할 수 있다. 이 파일은 가격·1분봉 또는 과거 날짜별 전체 거래가능 종목목록을 대신하지 않는다. [KR-06]

## 4. 미국주식 상세

### 4.1 Alpaca Basic: 무료 과거 SIP를 명시적으로 선택

공식 요금제는 Basic에 2016년부터의 주식·ETF 역사 데이터, 과거 API 200회/분을 표시한다. 무료 실시간 범위는 IEX지만, 공식 FAQ는 **구독 없이도 `end`가 최소 15분 이전인 역사 조회에 SIP를 사용할 수 있다**고 명시한다. 무료 과거 데이터를 일괄 IEX 전용으로 분류하면 안 된다. [US-01], [US-02]

권장 수집 요청의 형태는 다음과 같다. 실제 사용자 인증·허용 범위의 검증은 별도로 필요하다. [US-03]

```text
GET https://data.alpaca.markets/v2/stocks/bars
timeframe=1Min 또는 1Day
feed=sip
start=요청 시작일시
end=최근 15분보다 이전인 확정 종료일시
adjustment=raw
limit=10000
page_token=직전 응답 next_page_token
```

데이터 키는 `APCA-API-KEY-ID`, `APCA-API-SECRET-KEY` 헤더를 사용한다. 시세조회에 실계좌 주문 endpoint를 호출할 필요는 없다. 다음 공급원 특성을 기존 엔진의 수집 계약에 반영한다. [US-01], [US-03]

- 10,000건은 **응답 전체의 상한**이며 종목별 상한이 아니다.
- 종목명 우선 정렬이므로 첫 페이지에 일부 종목만 나올 수 있다. `next_page_token`이 남아 있으면 조회를 완료한 것이 아니다.
- `asof` 기본값은 현재 날짜이고 티커 변경 전 자료가 현재 티커 이름으로 반환될 수 있다. 안정된 종목 식별자와 티커 적용기간을 보존하고, 종목 매핑 기준일을 명시한다.
- `adjustment=raw` 원본과 분할·배당 등을 반영한 파생 시계열은 구분한다.
- SIP 오류 시 IEX로 조용히 대체하여 전체 미국시장 데이터라고 기록하지 않는다. IEX 대체 자료는 별도 공급원·커버리지로 표시한다.

Alpaca `/v2/assets`는 거래 및 데이터 소비용 종목 마스터이며 기본적으로 모든 상태를 포함한다. 다만 해당 API의 공개 명세에는 과거 기준일을 지정하는 PIT 마스터 기능이 없다. 현재 `active/inactive` 값만으로 10년 전체 상장폐지·종목변경 이력의 완전성을 인정하지 않는다. [US-04]

공식 Terms PDF는 개인·비상업 사용을 기본 범위로 두며, 자신의 앱을 통해 타인에게 제공하거나 다른 목적으로 사용하는 경우 사전 서면 통지 등 별도 조건을 명시한다. 개인 Basic 데이터 키가 존재하는 것만으로 회원 서비스 제공권까지 승인된 것은 아니다. [US-06]

### 4.2 Massive Basic: 최근 2년 PIT 자료의 보조 후보

현재 무료 Basic 안내에는 미국 주식, 5회/분, 과거 2년, EOD, 분봉, 기업행위가 포함된다. 개별 이용 목적 요금제로 표시된다. [US-05]

`/v3/reference/tickers`는 `date`, `active`, `delisted_utc`, `next_url`을 제공한다. 과거 기준일에 존재한 종목과 상장폐지 정보를 구성하는 데 유용하다. 그러나 **이 참조정보 endpoint도 무료 Basic 이력은 2년**이다. 10년 역사 universe를 무료로 확보하는 기능으로 표시하지 않는다. 현재 문서의 전체 참조자료 시작일과 계정 등급별 허용 범위는 구분해야 한다. [US-07]

### 4.3 Nasdaq와 SEC: 전체 과거 가격자료와 역할 구분

Nasdaq `nasdaqlisted.txt`·`otherlisted.txt`는 하루 중 갱신되는 현재 종목목록이다. 현재 목록을 과거 날짜에 그대로 적용하면 안 된다. 앞으로의 스냅샷 저장에는 활용할 수 있으나, 과거에 저장하지 않은 목록을 생성해 실제 기록처럼 표시하지 않는다. [US-08]

Nasdaq Daily List는 신규상장, 상장폐지, 티커·이름 변경, 배당·분할 등 기업행위를 제공하며 1999년부터의 이력을 명시한다. **별도 월 구독 상품이며 신청·승인이 필요한 경로**다. 이번 무상 작업에서 구매하거나 사용권을 취득하지 않았다. 또한 Nasdaq 상품 하나만으로 다른 모든 거래소의 역사 universe가 완성되는 것은 아니다. [US-09]

SEC 공개 API는 인증키 없이 기업별 공시 이력과 재무 XBRL을 제공한다. 기업·공시 증거의 보조 자료이며 OHLC·원본 1분봉 공급원은 아니다. [US-10]

### 5.2 별도 점검에서 확인한 공식 공개 경로

Upbit의 공식 분봉 API는 `GET /v1/candles/minutes/{unit}`, 현재 마켓목록은 `GET /v1/market/all`이다. 분봉 조회 `count`는 최대 200이고 `to`는 제외 경계다. 거래가 없었던 시간에는 봉이 생성되지 않으므로, 공급원에서 거래가 없어 빠진 봉과 수집 실패로 빠진 봉을 분리해야 한다. 현재 마켓목록에는 역사 기준일을 지정하는 기능이 문서화되어 있지 않다. [CR-01], [CR-02]

Upbit 공식 과거자료 다운로드 안내는 캔들을 2017-10-24부터 제공한다고 설명하지만 **현재 거래지원 중인 거래쌍 범위**이며, 모든 거래종료 종목의 복원을 보장하지 않는다. 별도 점검이 확인한 포털 안내에는 개인 투자 목적과 상업 이용·재배포 등의 제한이 있다. 포털 다운로드 가능 여부를 회원 서비스 원천데이터 제공권으로 해석하지 않는다. [CR-03]

Bitget의 최근 캔들 endpoint와 역사 캔들 endpoint는 구분한다. 역사 경로는 `GET /api/v2/mix/market/history-candles`, 현재 계약목록은 `GET /api/v2/mix/market/contracts`다. 공식 역사 조회의 최대 90일은 **한 요청의 start/end 기간폭 제한**이며 전체 보관기간이 90일이라는 뜻이 아니다. 문서에 없는 과거 전체 보유 범위를 임의로 단정하지 않는다. [CR-04]

Bitget 공식 역사 다운로드 포털도 존재하지만 종목별 가장 오래된 날짜, 거래종료 계약 완전성, 승인된 자동 파일 수집 방식까지 이번 점검에서 확인된 것은 아니다. API 약관의 데이터 재포장·재판매 제한과 공개 데이터 접근 가능성을 구분한다. 공식 상폐 공지는 이벤트 증거로 활용할 수 있지만, 하나의 공지로 전체 상장·폐지·재상장 이력을 입증할 수는 없다. [CR-05]~[CR-07]

무료 키나 토큰을 채팅에 붙여넣도록 요청하지 않는다. 사용할 수 있는 기존 서버 시크릿의 연결 여부는 비밀값을 출력하지 않고 확인한다. 공급원이 별도의 데이터 전용 키를 제공하면 이를 우선 사용한다. 증권사 키가 조회와 주문을 함께 지원하는 경우에도 연구 수집기는 허용한 시장데이터 endpoint만 사용한다.

새로운 서버 시크릿 추가·변경, 계정 가입, 공급권·약관 신청, 운영 활성화가 필요한 경우 구체적인 공급원·키 참조·변경항목을 준비한 뒤 기존 승인 범위와 대조한다. 현재 Draft 범위에서는 승인 전에 실제 설정을 변경하지 않는다. 데이터키를 실제 주문의 실행 권한으로 해석하지 않는다.

## 7. 기존 수집기와 연결할 검증 항목

다음은 조사 결과를 바탕으로 한 구현 요구사항이다. 구현·통과 여부는 root의 후속 기록에서 판정한다.

1. **공급원 목록과 실제 수집 증거를 구분한다.** 문서상의 지원 기간, 현재 키의 허용 범위, 실제 수신한 범위를 별도 보존한다.
2. **요청 범위와 실제 범위를 기록한다.** 요청 시작·끝, 실제 최초·최종 확정봉, 커서, 반환 개수, 중복·누락, 종료 이유를 남긴다.
3. **종목과 데이터 출처를 보존한다.** 시장·거래소·통화·계약 종류·티커 적용기간·공급원 feed를 함께 저장한다.
4. **현재 목록과 역사 목록을 구분한다.** 현재 상장·활성 종목만 수집했을 때는 당시 전체시장 recall을 계산하지 않는다.
5. **권한 범위를 기록한다.** 개인 연구, 내부 서비스, 회원 원천데이터 제공, 재배포 범위를 근거 문서와 함께 구분한다.
6. **부분 데이터로 전체 PASS를 만들지 않는다.** 제공되지 않는 기간, 알 수 없는 상장폐지·거래중지 이력, 누락 분봉은 명시적으로 차단한다.
7. **원본과 파생자료를 구분한다.** 원본 1분봉, 3·5·15분·시간봉 집계, 기업행위 조정자료, 과거 재생 결과를 별도로 표시한다.
8. **누락·오류를 0으로 숨기지 않는다.** 인증 실패, 호출 제한, 공급원 장애, 역사적 미지원, 거래 없음, 거래정지, 아직 미수집을 분류한다.

### 10.1 미국 Alpaca 과거 SIP 수집기: Draft 구현과 계약 테스트

`src/us-alpaca-historical-bars-v1.js`에 `collectAlpacaHistoricalBarsV1`을 추가했다. 기본 호출은 명시적 조회 동의나 전달된 데이터 Key·Secret이 없으면 `BLOCKED_DATA`, 공급원 GET 0회로 반환한다. 환경변수에서 키를 탐색하지 않으며 파일·계좌·주문 API에 접근하지 않는다.

고정된 Alpaca 과거 bars endpoint에 GET만 사용한다. `feed=sip`, `adjustment=raw`, `asof=-`, `sort=asc`, `limit=10000`을 명시하며 redirect와 브라우저 자격증명 전달을 허용하지 않는다. 공급원 오류를 IEX 대체 데이터로 숨기지 않는다. `asof=-`는 현재 티커로 자동 재표기하는 공급원 기능을 끄는 선택이고, 영구 종목 식별·티커 이력 검증을 대신하지 않는다.

단일 작업은 전달한 최대 20개 심볼, 시작·종료 시각이 걸치는 최대 31개 UTC 달력일, 기본 8페이지·최대 32페이지로 제한한다. 더 긴 전체 기간은 별도 작업으로 나누어 수집하며 3년 등의 전체 연구기간 제한을 만들지 않는다. 이 상한과 `maxPages`는 로컬 자원 제한이며 공급원의 역사 보관기간이 아니다.

공식 start/end는 봉 시작시각의 포함 경계이므로 요청·결과에 이를 표시한다. 무료 SIP 종료시각은 현재보다 최소 15분 이전이어야 한다. 원본 1분봉은 1분 정렬·범위·완결성을 검증하고, 일봉은 뉴욕 자정 시작과 다음 뉴욕 자정 종료를 사용해 DST의 23·25시간 날도 처리한다.

반환 결과는 원문 응답 SHA-256·크기, 원본 봉, 검증된 정규화 봉, 실제 최초·최종 봉시각, 페이지·GET 개수, 누락 요청심볼을 보존한다. 오류 HTTP 본문·자격증명·원문 커서값은 결과에 넣지 않는다. 페이지 종료 전 실패, 커서 반복·누락, 미요청 종목, 비정상 OHLC, 충돌 중복, 요청 종목의 데이터 부재는 모두 차단하며 확정 `count`는 `null`로 반환한다. 이미 유효하게 받은 자료는 별도 `retainedBarCount`와 원본·정규화 행에 남긴다.

계약 테스트 `tests/us-alpaca-historical-bars-v1.test.js`의 34개 검사가 성공했다. 인증 누락의 요청 0회, 종목별 페이지 편중, SIP·raw·asof 요청, 원문 바이트 해시, 기간 경계, 커서 문제, 데이터 오염·중복, 403·429 구분, 오류본문 비노출, DST 일봉 및 예상 밖 구현 예외 전달을 확인했다. 응답은 8 MiB 고정 버퍼와 12초 제한으로 읽으며 잘못된 UTF-8을 문자 치환으로 복구하지 않는다. **모든 외부 응답은 테스트 픽스처이며 실제 사용자 키로 Alpaca 데이터 조회를 검증한 결과는 아니다.** 전체 CI와 실제 데이터 접근 확인은 root의 별도 기록으로 남긴다.

### 10.2 현재 코인 목록 전체를 순회하는 원본 수집 경로

`public-native-crypto-roster-v1.js`는 고정된 공식 공개 GET 두 개로 현재 목록을 받아 원문 응답 SHA, 수신시각, 정규화 목록 SHA를 연결한다. 저장된 envelope를 다시 사용할 때 원문을 재정규화하여 경고·RWA 분류와 종목 목록의 일치도 검사한다. SHA는 파일 무결성 근거이며 독립적인 공급원 인증이나 역사 전체 종목 증명은 아니다.

Upbit KRW는 현재 `market_event` 경고를 보존하고 경고 종목도 목록에 포함한다. Bitget은 현재 정상 거래 중인 USDT perpetual 중 `isRwa=NO`만 코인 선물 목록에 포함하고, RWA·상품분류 미확인·비거래 종목은 제외 사유를 남긴다. 원래 식별자를 그대로 보존하며 현재 확인된 Han 계약명 3개도 기존 수집기·해시 경로·시간봉 변환기를 통과한다. 현재 목록에는 있지만 수집기가 지원하지 않는 문자가 나타나면 해당 종목을 명시적인 차단 행으로 남긴다.

`public-native-crypto-source-page-v1.js`와 `scripts/collect-public-native-source-page-v1.mjs`가 이 고정 목록의 최대 20종목과 닫힌 UTC 날짜 하나를 기존 Upbit/Bitget 1분봉 수집기에 연결한다. 다음 offset은 현재 목록의 방문 위치다. 날짜를 나눠 반복할 수 있으며 3년·366일·20,000봉을 전체 수집 기간의 제한으로 만들지 않는다. 이 단계는 역사 PIT manifest가 없는 상태의 공개 원본 확보 단계이며, 기존 PIT 입장 조건을 우회해 분석 권한을 만드는 경로가 아니다.

계획 모드는 요청 0회다. `capture` 및 `--read-public`을 명시한 실행만 공급원 GET을 할 수 있고 내부 의존성 객체가 이 권한·시장·날짜·원본 목록을 덮어쓰지 못한다. 원본 목록은 SHA가 일치하는 plain roster 또는 원문 연결까지 검증한 capture envelope를 사용할 수 있다. CLI 입력과 출력은 절대경로의 개인 파일을 사용하고 기존 출력 파일을 덮어쓰지 않는다. archive root는 미리 생성한 0700 디렉터리여야 한다.

동일 시장의 모든 종목에 걸쳐 요청 간격을 적용한다. 각 캔들 응답은 최대 2 MiB, JSON·UTF-8·리다이렉트·최종 출처를 검사하고 200행 상한은 기존 공급원 수집기가 추가 검사한다. HTTP 429·서버 장애·시간 초과는 방문하지 않은 종목을 0으로 처리하지 않고 해당 위치에서 재개하도록 남긴다. 예상하지 못한 코드 오류는 공급원 데이터 부족으로 숨기지 않는다.

기존 파일은 원본 digest, native sourceId, UTC 날짜, 과거 시점의 실제 가용성으로 오인되지 않는 수신시각을 확인한 뒤 재사용한다. 충돌 원본은 자동으로 최신 버전을 선택하지 않는다. `blockedSourceOffsets`는 확보하지 못한 종목, `partialSourceOffsets`는 확보한 일부 분봉 외에 확인이 필요한 종목을 나타낸다. **`nextOffset=null`은 현재 목록 방문 완료를 뜻하며 데이터 완전성 또는 과거 전체시장 완료를 뜻하지 않는다.** 부분 원본은 재실행만으로 변경하지 않고 기존 PIT의 명시적 보완·revision 선택 경로와 별도 검토 대상으로 남긴다.

### 10.4 저장 구조·실제 원본의 의미·미완료 경계

저장은 기존 시장 / 종목 SHA / UTC 날짜 / 원본 SHA의 immutable gzip 구조를 사용한다. 원본 1분봉을 그대로 OHLCV 행으로 보존하고, 기존 3·5·15분·1시간 변환기를 재사용한다. 수집 시각은 현재 수신시각으로 두므로 과거 T-60·T-30·T-15·T-5·T0 검색에 실제로 이용 가능했던 증거로 바뀌지 않는다.

**캔들 archive는 원래 공급원 봉의 정규화 OHLCV이며 HTTP 원문 전체가 아니다.** 기존 exact-key 계약상 `quoteVolume` 등 부가 필드는 이 archive에 포함하지 않는다. 현재 roster의 HTTP 원문, 오래된 두 공급원 probe 원문은 별도로 보존했다. 캔들 원문·부가필드까지 보존하는 추가 저장 계약은 이번 변경으로 완료했다고 표시하지 않는다.

전체 수집은 날짜·최대 20종목 단위로 증분 진행하고 저장된 revision을 재사용한다. 기존 PIT 실행기와 같은 writer lock을 쓰며, 기본 로컬 상한 2 GiB·파일시스템 잔여 2 GiB·종목당 최대 3 MiB의 사전 여유 공간을 검사한다. 긴 기간의 원본은 완료된 날짜 단위로 검증된 private 장기 저장소에 이관하고 digest manifest로 복원해야 한다. 이번에는 운영 저장소를 생성·연결하거나 자동 삭제·백그라운드 일정을 활성화하지 않았다.

이번 변경은 다음 조건을 계속 유지한다.

```text
profitabilityProven=false
OOSPassCount=0
trueMarketWideRecall=null
paperAdmissionAllowed=false
executionAuthority=NONE
```

국내·미국 주식의 승인된 실제 데이터 접근, 전 기간 PIT 전체 종목·상장폐지·거래상태, 원본 일봉과 필요한 분봉, 비용·독립 OOS·워크포워드 증거가 부족하다. 원본 확보 상태를 앱의 수익성·Paper PASS로 승격하지 않았고, 통합 앱의 장기 백테스터 연결·관리자 실제 결과 게시·자동모의매매 폐루프 완료도 주장하지 않는다. 기존 Draft만 갱신하며 Ready·Merge·Staging·Production·실거래 활성화는 하지 않는다.

### 10.5 전용 로컬 회귀 검증

최종 수정 소스에 대해 기존 whole-PIT GitHub workflow가 열거한 Node 테스트 41개 파일을 한 번에 실행하여 **444/444 PASS**를 확인했다. 실패·취소·건너뜀은 모두 0이었다. 기존 native PIT 및 stock source Python scorer의 `--self-test`도 각각 통과했다. 가상 데이터는 수집기·저장·재생 계약 검증에만 사용했고 위 실제 API 표본과 구분했다.

새 source page의 회귀에는 계획 모드 요청 0회, 원문과 roster 연결, 20종목 페이지·재개, 출처가 다른 캐시 거부, 1분만 존재하는 상장 경계 원본 보존, Han 식별자, 부분 원본 목록, 429·시간 초과·과대 응답 및 코드 오류 전파가 포함된다. 기존 1,440분 원본으로 3분 480개·5분 288개·15분 96개·1시간 24개를 만드는 변환 계약도 재사용해 검증했다.

이는 로컬 코드·계약 검증 결과다. 정확한 새 커밋의 GitHub Actions 상태, 브라우저 검사 및 실제 확대 수집 결과는 실행 완료 후 #1102와 Draft #1534의 결과 댓글에 기록한다. 실패한 CI를 수익성 또는 데이터 0으로 바꾸지 않는다.
