## 0. 작업 범위와 금지사항

이 문서는 코드 구현 전에 현물용 검색기와 선물용 검색기의 판단 기준, 결과 형식, 자동주문 연결 규격을 고정하기 위한 설계서다.

이번 문서 단계에서는 다음 작업을 하지 않는다.

- 실주문 환경변수 활성화

- 원본 브랜치 병합

- `stock-analyzer/src/components/detail/lazy-panel.tsx` 및 lazy-panel 관련 파일 수정

모든 신호는 수익을 보장하는 예측값이 아니라 후보 비교와 위험 통제를 위한 모델 점수다.

# 1. 최종 구조

검색기는 두 종류로 분리한다.

```text
현물 검색기
 ├─ 국내주식
 │   └─ 기술 + 외국인·기관 수급 + 거래대금 + 업종 상대강도 + 공시·실적
 ├─ 해외주식
 │   └─ 기술 + 지수·섹터 상대강도 + 실적·가이던스 + 장전·장후 + 뉴스
 └─ 업비트 현물
     └─ 기술 + 체결강도 + 호가불균형 + 거래대금 가속 + BTC 상대강도

선물 검색기
 └─ 비트겟 USDT 선물
     └─ 롱·숏 기술점수 + 미결제약정 + 펀딩 + 베이시스
        + 체결·호가 + 시장방향 + 손익비 + 주문가능성
```

검색기별 점수 엔진은 분리하지만 다음 기반 기능은 공용으로 사용한다.

- 캔들 정규화
- 중복 제거와 시간순 정렬
- 데이터 최신성 검사
- SMA·EMA·RSI·MACD·볼린저·ATR·스토캐스틱·VWAP
- 평균 거래량과 거래량 비율
- 최근 고점·저점
- 지지선·저항선
- 추세선·박스권·캔들 패턴
- 데이터 공급자와 계산 버전 기록
- `signalSnapshot` 생성 및 검증

# 2. 공통 검색 원칙

## 2.1 가짜 데이터 금지

다음 경우에는 점수를 억지로 만들지 않는다.

- 필수 캔들 수 부족
- 현재가 없음
- 지표 계산 결과가 `NaN` 또는 무한대
- 데이터 갱신시각이 허용 범위를 초과
- 시장별 필수 데이터가 누락

결과는 `DATA_INSUFFICIENT`, `DATA_STALE`, `PROVIDER_ERROR` 중 하나로 제외 사유를 표시한다.

## 2.2 2단계 검색

### 1차 빠른 검색

전체 시장에서 가벼운 데이터만 이용해 후보를 축소한다.

- 거래대금
- 거래량
- 등락률
- 스프레드
- 거래 가능 상태
- 최소 유동성
- 경고·위험 종목 여부

기본 후보 수:

- 국내주식: 최대 50
- 해외주식: 최대 50
- 업비트 현물: 최대 40
- 비트겟 선물: 최대 40

### 2차 정밀 분석

1차 후보에만 다음을 계산한다.

- 다중 시간봉
- 전체 기술지표
- 지지·저항과 진입 위치
- 시장별 전용 데이터
- 뉴스·공시·실적 또는 OI·펀딩·베이시스
- 예상 진입가·손절가·목표가·손익비

최종 화면에는 기본 10개, 최대 20개를 표시한다.

## 2.3 다중 시간봉

### 국내·해외주식

- 큰 추세: 일봉
- 중간 추세: 60분봉
- 진입 신호: 15분봉
- 단기 확인: 5분봉

### 업비트 현물

- 큰 추세: 4시간봉
- 중간 추세: 1시간봉
- 진입 신호: 15분봉
- 단기 확인: 5분봉

### 비트겟 선물

- 큰 방향: 4시간봉
- 현재 추세: 1시간봉
- 진입 조건: 15분봉
- 실제 주문 타이밍: 5분봉

사용자가 다른 봉을 선택해도 큰 방향과 중간 추세 검사는 유지한다.

# 3. 현물 검색기

현물 검색기는 숏 진입 후보를 만들지 않는다. 결과 분류는 다음으로 통일한다.

- `STRONG_BUY`: 적극 매수 후보
- `BUY`: 매수 후보
- `PULLBACK_WAIT`: 눌림목 대기
- `WATCH`: 관망
- `REDUCE`: 보유 비중 축소
- `AVOID`: 매수 회피

## 3.1 현물 공통 100점 구성

| 영역 | 최대점수 | 내용 |
|---|---:|---|
| 다중 시간봉 추세 | 20 | 큰 추세·중간 추세·진입봉 방향 일치 |
| 모멘텀 | 15 | 이평 배열, RSI, MACD, 스토캐스틱, 볼린저 |
| 거래량·거래대금 | 15 | 평균 대비 증가율, 거래대금 가속, 돌파 확인 |
| 진입 위치 | 10 | 지지·저항, VWAP, 신고가 추격 위험, 손익비 |
| 시장별 전용 데이터 | 30 | 국내·해외·업비트별 별도 항목 |
| 데이터 신뢰도 | 10 | 완성도, 최신성, 공급자 상태, 유동성 |
| 위험 감점 | 최대 -40 | 과열·급등·저유동성·경고·이벤트 위험 |

최종 점수는 `0~100`으로 제한한다.

## 3.2 공통 기술점수 세부 기준

### 다중 시간봉 추세 20점

- 큰 시간봉 상승 추세: +8
- 중간 시간봉 상승 추세: +6
- 진입 시간봉 상승 또는 반전 확인: +4
- 세 시간봉 방향 일치: +2
- 큰 시간봉 하락 중 단기 반등만 발생: 최대 6점으로 제한

### 모멘텀 15점

- SMA 5 > 20 > 60 정배열: +4
- 현재가가 SMA20·SMA60 위: +2
- EMA12 > EMA26: +2
- MACD가 Signal 상향 돌파 또는 Histogram 증가: +2
- RSI 50~68: +2
- 스토캐스틱 상승 전환: +1
- 볼린저 중심선 회복 또는 상단 돌파 후 유지: +2

### 거래량·거래대금 15점

- 최근 거래량이 20봉 평균 1.5배 이상: +4
- 2배 이상이며 가격 상승 동반: 추가 +2
- 거래대금 증가율 상위권: +4
- 돌파봉 거래량 확인: +3
- 거래량 감소 속 가격만 상승: -3

### 진입 위치 10점

- 주요 지지선 또는 VWAP 인근: +3
- 저항 돌파 후 재지지 확인: +3
- 예상 손익비 1.5 이상: +2
- 예상 손익비 2.0 이상: 추가 +1
- 최근 고점에서 과도하게 이격되지 않음: +1

# 7. 비트겟 선물 검색기

선물 검색기는 롱과 숏 점수를 독립적으로 계산한다.

결과 분류:

- `LONG_STRONG`
- `LONG`
- `SHORT_STRONG`
- `SHORT`
- `VOLATILITY_WAIT`
- `NO_ENTRY`
- `EXIT_LONG`
- `EXIT_SHORT`

## 7.1 선물 롱·숏 100점 구성

| 영역 | 최대점수 | 내용 |
|---|---:|---|
| 다중 시간봉 방향 | 20 | 4H·1H·15m·5m 방향 정합성 |
| 추세·모멘텀 | 15 | 이평, RSI, MACD, 볼린저, ATR |
| 가격·미결제약정 | 15 | 가격 변화와 OI 변화 조합 |
| 펀딩·베이시스 | 10 | 과밀 방향, 마크·인덱스 괴리 |
| 체결·호가 | 10 | 공격적 매수·매도, 불균형, 스프레드 |
| BTC·시장 국면 | 10 | BTC 방향, 알트 확산, 시장 상승 비율 |
| 진입 위치·손익비 | 10 | 지지·저항, 손절 거리, 기대 손익비 |
| 주문 가능성 | 10 | 계약상태, 최소수량, 레버리지, 슬리피지 |
| 위험 감점 | 최대 -50 | 청산위험, 과열, 급등락, 데이터 지연 |

롱·숏 양쪽이 모두 높거나 점수 차가 작으면 진입하지 않는다.

기본 진입 조건:

- 선택 방향 점수 75점 이상
- 반대 방향과 12점 이상 차이
- 다중 시간봉 큰 방향과 충돌하지 않음
- 예상 손익비 1.5 이상
- 강제 차단 조건 없음

## 7.2 가격과 OI 조합

| 가격 | OI | 해석 | 롱/숏 처리 |
|---|---|---|---|
| 상승 | 상승 | 신규 롱 또는 추세 확장 가능성 | 롱 가점 |
| 하락 | 상승 | 신규 숏 또는 하락 추세 확장 | 숏 가점 |
| 상승 | 하락 | 숏 청산 가능성 | 추격 롱 제한, 스퀴즈 표시 |
| 하락 | 하락 | 롱 청산 가능성 | 추격 숏 제한, 청산 표시 |

OI는 절대값이 아니라 최근 5분·15분·1시간 변화율과 거래량 대비 증가율을 함께 본다.

## 7.3 펀딩·베이시스

- 펀딩 과도한 양수: 롱 감점, 숏 과밀 해소 가능성 표시
- 펀딩 과도한 음수: 숏 감점, 롱 반등 가능성 표시
- 마크가격과 인덱스가격 괴리 확대: 과열 감점
- 펀딩 정산 직전 급변: 신규 진입 제한 가능
- 최근 펀딩 방향이 빠르게 변할 때 변동성 경고

## 7.4 선물 검색 모드

- `TREND_LONG`: 추세추종 롱
- `TREND_SHORT`: 추세추종 숏
- `OI_BREAKOUT`: OI 증가 돌파
- `SHORT_SQUEEZE`: 숏 스퀴즈 후보
- `LONG_LIQUIDATION`: 롱 청산 후보
- `FUNDING_CONTRARIAN`: 과도한 펀딩 역추세
- `VOLATILITY_BREAKOUT`: 변동성 돌파
- `PULLBACK_ENTRY`: 눌림·되돌림
- `NO_ENTRY`: 진입 금지

## 7.5 선물 강제 차단

다음 조건은 점수 감점이 아니라 주문계획 생성 자체를 차단한다.

- 계약 거래상태 비정상
- 시세·캔들·OI 데이터 오래됨
- 최소 주문수량 또는 최소 주문금액 미달
- 서버 최대 레버리지 초과
- 스프레드 기준 초과
- 예상 슬리피지 기준 초과
- 동일 종목 실제 포지션 존재
- 동일 종목 주문 처리 중
- 재진입 대기시간 미경과
- 일일 주문 한도 도달
- 동시 포지션 한도 도달
- 긴급정지 활성
- 사용가능 증거금 부족
- 계획 후 가격변동 허용치 초과

# 8. 공통 결과 카드 규격

모든 후보 카드에는 다음을 표시한다.

- 순위
- 종목명과 심볼
- 시장
- 종합점수
- 방향 또는 의견
- 큰 시간봉 방향
- 중간 시간봉 방향
- 진입 시간봉 방향
- 현재가와 데이터 갱신시각
- 추천 진입구간
- 손절 또는 관점 무효화 가격
- 목표가 1·2
- 예상 손익비
- 가장 강한 근거 최대 3개
- 위험요인 최대 3개
- 데이터 완성도
- 자동주문 가능 여부
- 자동주문 차단 사유

예시:

```text
DOGEUSDT · 롱 78점
4H 상승 / 1H 상승 / 15m 돌파
OI +8.2% · 거래량 2.1배 · BTC 방향 일치
진입 0.123~0.125 / 손절 0.119 / 목표1 0.129 / 목표2 0.132
손익비 1.9 / 위험: 펀딩 과열, 24시간 급등
```

점수만 표시하고 근거·위험·갱신시각을 숨기는 UI는 허용하지 않는다.

# 9. `signalSnapshot` 공통 규격

검색 화면과 자동주문 서버는 점수를 따로 계산하지 않는다. 검색기가 만든 동일한 스냅샷을 서버가 검증해서 주문계획에 사용한다.

```ts
export type SignalAssetClass =
  | 'KR_STOCK'
  | 'US_STOCK'
  | 'UPBIT_SPOT'
  | 'BITGET_FUTURES';

export type SignalDirection =
  | 'BUY'
  | 'WATCH'
  | 'REDUCE'
  | 'AVOID'
  | 'LONG'
  | 'SHORT'
  | 'NO_ENTRY';

export interface SignalSnapshot {
  id: string;
  version: string;
  assetClass: SignalAssetClass;
  provider: 'kiwoom' | 'upbit' | 'bitget';
  symbol: string;
  name: string;
  market: string;
  direction: SignalDirection;

  score: number;
  oppositeScore: number | null;
  confidence: number;
  dataCompleteness: number;

  currentPrice: number;
  priceFetchedAt: string;
  generatedAt: string;
  expiresAt: string;

  primaryTimeframe: string;
  candleCloseTime: string;
  timeframeStates: Array<{
    timeframe: string;
    direction: 'UP' | 'DOWN' | 'SIDEWAYS';
    score: number;
    candleCloseTime: string;
  }>;

  indicators: {
    sma5: number | null;
    sma20: number | null;
    sma60: number | null;
    sma120: number | null;
    ema12: number | null;
    ema26: number | null;
    rsi14: number | null;
    macd: number | null;
    macdSignal: number | null;
    macdHistogram: number | null;
    atr14: number | null;
    atrPercent: number | null;
    stochasticK: number | null;
    stochasticD: number | null;
    vwap: number | null;
    volumeRatio: number | null;
  };

  marketSpecific: Record<string, number | string | boolean | null>;

  support: number | null;
  resistance: number | null;
  entryLow: number | null;
  entryHigh: number | null;
  stopPrice: number | null;
  target1: number | null;
  target2: number | null;
  rewardRiskRatio: number | null;

  reasons: string[];
  risks: string[];
  blockers: string[];
  autoTradeEligible: boolean;

  scoring: {
    model: 'SPOT_V1' | 'FUTURES_V1';
    components: Record<string, number>;
    penalties: Record<string, number>;
  };

  integrity: {
    sourceHash: string;
    snapshotHash: string;
  };
}
```

## 9.1 스냅샷 검증 규칙

자동주문 서버는 다음을 모두 확인한다.

- `snapshotHash` 일치
- 현재 사용자에게 발급된 스냅샷인지
- 만료되지 않았는지
- 캔들 종료시각이 허용 범위 안인지
- 현재가격이 스냅샷 가격에서 허용 범위 이상 움직이지 않았는지
- 점수 계산 버전이 서버 지원 버전인지
- `autoTradeEligible=true`인지
- 차단 사유가 비어 있는지
- 동일 스냅샷이 이미 사용되지 않았는지

화면의 점수와 주문계획의 점수가 다르면 주문계획을 만들지 않는다.

# 10. 권장 API 구조

```text
GET  /api/signals/spot/scan
GET  /api/signals/futures/scan
GET  /api/signals/snapshots/:id
POST /api/signals/snapshots/:id/validate

POST /api/auto-trade/plan
POST /api/auto-trade/execute
POST /api/auto-trade/monitor
POST /api/auto-trade/kill-switch
GET  /api/auto-trade/journal
GET  /api/auto-trade/positions
```

`plan` 요청에는 사용자가 만든 임의 점수나 임의 목표가를 보내지 않는다. `signalSnapshotId`와 사용자 위험 설정만 전달한다.

```json
{
  "signalSnapshotId": "sig_...",
  "riskProfileId": "risk_...",
  "executionMode": "PAPER"
}
```

서버는 스냅샷을 다시 조회하고 검증한 뒤 주문수량과 주문계획을 계산한다.

# 11. 화면 구성

## 11.1 상단 구조

- `신호검색`
- `차트중계`
- `자동매매`

시장 선택:

- `주식`
- `코인`

세부 시장:

- 주식: `국내`, `해외`
- 코인: `현물·업비트`, `선물·비트겟`

현물과 선물을 선택하면 해당 검색기의 모드·점수·결과 카드가 완전히 바뀐다.

## 11.2 검색 결과 영역

- 검색 모드 선택
- 기준 시간봉 선택
- 롱·숏 또는 매수 후보 탭
- 상위 후보 10개
- 데이터 갱신 상태
- 자동 갱신 켜기·끄기
- 강제 새로고침

후보를 누르면 전체 화면 상세 분석으로 이동한다. 메인 화면 아래로 상세 패널을 무한히 펼치지 않는다.

## 11.3 자동매매 연결

검색 결과 카드에는 다음 상태를 표시한다.

- `모의계획 가능`
- `실주문 계획 가능`
- `데이터 부족`
- `위험조건 차단`
- `이미 보유 중`
- `재진입 대기`

검색기에서 직접 실제 주문을 보내지 않는다. 자동매매 화면에서 동일한 `signalSnapshot`을 불러와 위험한도와 서버 안전검사를 통과한 뒤 계획을 만든다.

# 12. 갱신과 캐시

권장 기본값:

- 티커·호가: 5~10초 또는 WebSocket
- 5분·15분 신호: 10~15초 확인, 완성봉 기준 계산
- 1시간 신호: 30초
- 4시간·일봉 신호: 60초
- 전체 정밀검색: 30초~2분
- 뉴스·공시·실적: 공급자별 별도 TTL

완성되지 않은 현재 봉은 화면 참고값으로 표시할 수 있지만, 기본 자동주문 점수는 완성봉을 기준으로 한다. 미완성봉 신호를 사용할 경우 별도 `INTRABAR` 표시와 더 짧은 만료시간을 적용한다.

# 13. 테스트 기준

## 13.1 점수 일치

- 동일한 캔들·시장 데이터 입력에서 프런트와 서버 점수 일치
- 검색 결과 78점이면 주문계획도 동일 스냅샷 78점
- 점수 버전이 다르면 주문 차단

## 13.2 데이터 안전

- 캔들 부족 시 후보 제외
- `NaN`, 무한대, 음수 거래량 방지
- 오래된 시세 차단
- 공급자 오류를 0점 종목으로 오인하지 않음

## 13.3 현물

- 국내 수급 데이터 누락 처리
- 해외 실적·뉴스 미지원 시 `데이터 없음`
- 업비트 호가·체결 중단 시 주문 자격 제거
- 급등 추격 감점 확인

## 13.4 선물

- 가격·OI 네 조합 테스트
- 과도한 펀딩 감점 테스트
- 롱·숏 점수 차 미달 시 `NO_ENTRY`
- 최소수량·스프레드·슬리피지 차단
- 동일 종목 중복 및 재진입 차단
- 긴급정지 상태에서 주문계획·실행 차단

## 13.5 복구

- 서버 재시작 후 스냅샷 사용 여부 복구
- 진행 중 주문 재동기화
- 부분체결·미체결·거절 상태 기록
- 중복 요청에 같은 주문을 두 번 보내지 않음

# 14. 구현 순서

## 1단계: 공통 형식

- `SignalSnapshot` 타입
- 점수 계산 버전
- 캔들·시장 데이터 최신성 검사
- 스냅샷 해시와 저장소
- 단위 테스트

## 2단계: 현물 검색기

- 국내주식 전용 점수
- 해외주식 전용 점수
- 업비트 현물 전용 점수
- 공통 결과 카드
- 검색 모드와 필터

## 3단계: 선물 검색기

- 비트겟 OI·펀딩·베이시스 수집
- 롱·숏 점수 엔진
- 주문 가능성·차단 검사
- 기존 15분 검색 화면과 공통 엔진 연결

## 4단계: 자동매매 계획 연결

- `signalSnapshotId` 기반 계획 API
- 화면과 서버 점수 동일성 검증
- PAPER 모드 계획·실행
- 매매일지와 포지션 감시

## 5단계: 무인 실행 준비

- 서버 상시 작업자
- 재시작 복구
- 중복 방지
- 부분체결·체결확인
- 긴급정지
- Shadow 모드 장시간 검증

## 6단계: 실주문 활성화 검토

실주문 활성화는 별도 승인 작업으로 분리한다. 코드 작성 또는 빌드 성공만으로 실주문 환경변수와 실제 계좌 주문을 활성화하지 않는다.

# 15. 완료 조건

다음 조건을 모두 충족해야 검색기 통합 완료로 본다.

- 현물과 선물 엔진이 분리됨
- 시장별 전용 데이터를 실제 공급자에서 받음
- 화면과 서버가 동일한 `signalSnapshot`을 사용함
- 점수·근거·위험·차단 사유가 모두 표시됨
- 데이터 부족 시 가짜 점수를 만들지 않음
- PAPER 모드에서 검색→계획→모의체결→일지 흐름 검증
- 종목상세와 lazy-panel 파일을 수정하지 않음
- 실주문 환경변수를 건드리지 않음
