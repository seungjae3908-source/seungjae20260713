# 자동매매 검색기 설계 명세

작성일: 2026-07-26
대상 브랜치: `agent/auto-trading-route-hardening`
상태: 설계 승인 전 문서

## 1. 목적

자동매매 검색기를 다음 두 계열로 분리한다.

- 현물용 검색기
  - 국내주식
  - 해외주식
  - 업비트 코인 현물
- 선물용 검색기
  - 비트겟 USDT 무기한 선물

검색 화면과 자동주문 서버가 서로 다른 점수를 다시 계산하지 않도록, 동일한 `signalSnapshot`을 공유한다.

## 2. 공통 원칙

1. 가짜 데이터와 임의 보정값을 만들지 않는다.
2. 데이터가 부족하면 후보 제외 또는 `DATA_INSUFFICIENT`로 표시한다.
3. 검색 결과 점수와 자동주문 점수는 같은 계산 버전과 스냅샷을 사용한다.
4. 현물과 선물은 점수 체계를 분리한다.
5. 주문 가능 여부는 점수와 별도로 강제 차단 조건을 둔다.
6. 실주문 기능은 별도 승인 전까지 활성화하지 않는다.
7. 모든 시각은 공급자 시각, 수집 시각, 캔들 종료 시각을 구분해 저장한다.
8. 동일 종목·동일 신호·동일 캔들에 대한 중복 주문을 차단한다.

# 3. 현물용 검색기

## 3.1 대상 시장

- `KR_STOCK`: 국내주식
- `US_STOCK`: 해외주식
- `UPBIT_SPOT`: 업비트 원화 현물

## 3.2 결과 방향

- `STRONG_BUY`: 적극 매수 후보
- `BUY`: 매수 후보
- `PULLBACK_WAIT`: 눌림목 대기
- `WATCH`: 관망
- `REDUCE`: 보유 비중 축소
- `AVOID`: 신규 매수 회피

현물 검색기에서는 숏 진입 신호를 생성하지 않는다.

## 3.3 기본 시간봉

### 국내·해외주식

- 큰 추세: 일봉
- 중간 추세: 60분봉
- 진입 확인: 15분봉
- 초단기 타이밍: 5분봉

### 업비트 현물

- 큰 추세: 4시간봉
- 중간 추세: 1시간봉
- 진입 확인: 15분봉
- 초단기 타이밍: 5분봉

# 4. 코인 선물용 검색기

## 4.1 대상 시장

- `BITGET_USDT_FUTURES`

## 4.2 결과 방향

- `LONG_STRONG`
- `LONG`
- `SHORT_STRONG`
- `SHORT`
- `VOLATILITY_WAIT`
- `NO_ENTRY`
- `EXIT_LONG`
- `EXIT_SHORT`

## 4.3 기본 시간봉

- 큰 방향: 4시간봉
- 추세 확인: 1시간봉
- 진입 신호: 15분봉
- 주문 타이밍: 5분봉

사용자가 화면에서 다른 시간봉을 선택해도 큰 방향 확인 시간봉은 별도로 유지한다.

## 4.4 선물 전용 점수표

롱 점수와 숏 점수를 각각 100점 기준으로 계산한다.

| 영역 | 배점 |
|---|---:|
| 다중 시간봉 방향 일치 | 20 |
| 추세·모멘텀 | 15 |
| 가격·미결제약정 조합 | 15 |
| 펀딩비·마크/인덱스 괴리 | 10 |
| 체결·호가 흐름 | 10 |
| BTC·시장 전체 방향 | 10 |
| 진입 위치·손익비 | 10 |
| 계약·유동성·체결 가능성 | 10 |

### 선물 위험 감점

- 펀딩 과밀: 최대 -12
- OI 급증 후 가격 역행: 최대 -12
- 마크·인덱스 괴리 과다: 최대 -8
- 스프레드·예상 슬리피지 과다: 최대 -8
- 최근 급등·급락 추격 위험: 최대 -10
- 상장 초기·거래상태 이상: 강제 차단
- 최소 주문수량·최소 금액 미달: 강제 차단
- 최대 레버리지 또는 서버 상한 초과: 강제 차단

## 4.5 가격과 OI 해석

| 가격 | OI | 해석 |
|---|---|---|
| 상승 | 상승 | 신규 롱 유입 가능성 |
| 하락 | 상승 | 신규 숏 유입 가능성 |
| 상승 | 하락 | 숏 청산 가능성 |
| 하락 | 하락 | 롱 청산 가능성 |

OI는 단독 매매 신호로 사용하지 않고 가격·거래량·펀딩과 함께 사용한다.

## 4.6 펀딩·베이시스 기능

- 현재 펀딩비
- 최근 펀딩비 변화
- 다음 펀딩 시각
- 마크가격과 인덱스가격 괴리율
- 과도한 양수 펀딩 시 롱 감점
- 과도한 음수 펀딩 시 숏 감점
- 펀딩 역추세 전략은 별도 검색 모드에서만 허용

## 4.7 선물 검색 모드

- 추세추종 롱
- 추세추종 숏
- OI 증가 돌파
- 숏 스퀴즈 후보
- 롱 청산 후보
- 펀딩 과밀 역추세
- 변동성 돌파
- 눌림·되돌림 진입
- 진입 금지 종목

# 5. 2단계 검색 구조

## 5.1 1차 빠른 검색

전체 시장에서 다음 데이터만 이용한다.

- 거래대금
- 거래량
- 등락률
- 현재가
- 스프레드
- 거래 가능 상태
- 최소 유동성

시장별 상위 30~50개 후보를 남긴다.

## 5.2 2차 정밀 분석

1차 후보에만 다음을 수행한다.

- 다중 시간봉 캔들
- 전체 기술지표
- 지지·저항·패턴
- 국내 수급·공시·실적
- 해외 상대강도·실적·뉴스
- 업비트 체결·호가
- 비트겟 OI·펀딩·롱숏비율
- 진입가·손절가·목표가·손익비

## 5.3 캐시와 갱신 주기

- 현재가·호가: 1~5초 또는 WebSocket
- 1·3·5·15분봉: 10~15초
- 30분·1시간·4시간봉: 30초
- 일봉 이상: 60초
- 뉴스·공시: 1~5분
- 실적·재무: 1일 또는 이벤트 발생 시

같은 공급자·종목·시간봉 요청은 서버에서 합쳐 중복 호출을 막는다.

# 6. signalSnapshot 규격

```ts
export type SignalSnapshot = {
  id: string;
  version: string;
  assetClass: 'STOCK' | 'CRYPTO_SPOT' | 'CRYPTO_FUTURES';
  market: 'KR' | 'US' | 'UPBIT' | 'BITGET';
  symbol: string;
  displayName: string;
  direction:
    | 'STRONG_BUY'
    | 'BUY'
    | 'PULLBACK_WAIT'
    | 'WATCH'
    | 'REDUCE'
    | 'AVOID'
    | 'LONG_STRONG'
    | 'LONG'
    | 'SHORT_STRONG'
    | 'SHORT'
    | 'VOLATILITY_WAIT'
    | 'NO_ENTRY'
    | 'EXIT_LONG'
    | 'EXIT_SHORT';
  score: number;
  oppositeScore?: number;
  riskScore: number;
  dataCompleteness: number;
  provider: string;
  strategyMode: string;
  primaryTimeframe: string;
  higherTimeframes: Array<{
    timeframe: string;
    direction: 'UP' | 'DOWN' | 'SIDEWAYS';
    score: number;
  }>;
  currentPrice: number;
  entryZone: { low: number; high: number } | null;
  stopPrice: number | null;
  target1: number | null;
  target2: number | null;
  rewardRiskRatio: number | null;
  indicators: Record<string, number | string | boolean | null>;
  reasons: string[];
  risks: string[];
  blockers: string[];
  candleClosedAt: string;
  providerFetchedAt: string;
  generatedAt: string;
  expiresAt: string;
  fingerprint: string;
};
```

## 6.1 fingerprint 구성

다음 값을 안정적으로 직렬화한 뒤 SHA-256으로 생성한다.

- 점수 계산 버전
- 시장·심볼
- 전략 모드
- 주 시간봉
- 캔들 종료시각
- 방향
- 진입구간·손절·목표

자동주문은 동일 fingerprint의 주문을 중복 실행하지 않는다.

## 6.2 자동주문 검증

자동주문 서버는 주문 직전에 다음을 재검사한다.

1. 스냅샷 만료 여부
2. 현재가와 스냅샷 가격의 차이
3. 데이터 공급자 최신성
4. 강제 차단 사유
5. 계좌 잔고와 주문 상한
6. 동시 보유와 일일 주문 한도
7. 동일 fingerprint 중복 실행
8. 손익비 기준
9. 시장별 거래 가능 시간과 거래 상태

점수 전체를 다시 계산하지 않고 동일 스냅샷을 검증한다. 가격 변동이 허용 범위를 넘으면 새 스냅샷을 생성한다.

# 9. 구현 순서

## 1차

- 공통 타입과 `signalSnapshot` 생성기
- 점수 계산 버전 관리
- fingerprint와 만료 검증
- 단위 테스트

## 2차

- 비트겟 선물 기존 신호검색 계산을 서버 공통 엔진으로 이전
- 화면과 서버 점수 일치 테스트
- 실주문 비활성 상태에서 주문계획 검증

## 3차

- 업비트 현물 검색기 통합
- 호가·체결·BTC 상대강도 추가

# 10. 완료 조건

- 같은 캔들 입력에서 화면 점수와 서버 점수가 일치한다.
- 검색 결과의 `snapshotId`가 주문계획까지 유지된다.
- 만료·가격 이탈·데이터 지연 시 주문이 차단된다.
- 현물 검색기는 숏 주문을 만들지 않는다.
- 선물 검색기는 롱·숏 점수와 위험 감점을 별도로 제공한다.
- 데이터가 없을 때 임의 점수를 만들지 않는다.
- 종목상세와 `lazy-panel` 관련 파일을 수정하지 않는다.
- 원본 브랜치에 병합하지 않는다.
