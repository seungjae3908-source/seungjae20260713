# Phase 6 결정론적 모의매매와 로컬 거래일지

## 목적

Phase 6는 실제 거래소 주문과 완전히 분리된 `paper-only` 계산 계층이다. 공개 시장 데이터와 공개 계약 규칙을 입력으로 받고, Phase 3 `calculateTradingRisk`를 통과한 요청만 모의주문·모의체결·포지션·거래일지 상태로 변환한다.

모든 API와 화면은 다음 안전 계약을 유지한다.

```text
mode = paper-only
orderSubmitted = false
exchangeRequestSent = false
```

실제 주문 모듈, 비공개 거래소 API, API Key·Secret, 계좌·잔고·포지션 조회, 자동매매, 운영 DB는 사용하지 않는다.

## 구조

- 서버 `paper-trading-engine.service.ts`: 상태를 저장하지 않는 순수 결정론적 계산 엔진
- 서버 `POST /api/paper-trading/evaluate`: 클라이언트가 보낸 현재 상태와 단일 액션을 검증하고 다음 상태를 반환
- 클라이언트 `paper-trading.ts`: API 계약, 버전 1 로컬 저장, JSON 내보내기·가져오기, 손상 복구
- 화면 `/paper-trading`: 계좌, 주문, 포지션, 주문 목록, 거래일지, 기초 통계

서버 API는 영구 상태를 보유하지 않는다. 페이지 새로고침 복원은 브라우저 localStorage에서만 수행한다.

## 주문 상태 머신

허용 전이:

```text
pending -> filled
pending -> cancelled
pending -> rejected
pending -> expired
```

`filled`, `cancelled`, `rejected`, `expired`에서 추가 전이는 허용하지 않는다. 모든 액션은 `eventId`를 요구하며 최근 500개 이벤트 ID를 저장해 같은 이벤트가 재전송돼도 이중 체결하지 않는다.

## 주문 유형과 체결

### 시장가

- 롱 진입: 공개 ask를 기준으로 불리한 슬리피지 적용
- 숏 진입: 공개 bid를 기준으로 불리한 슬리피지 적용
- bid·ask가 없으면 mark, last 순으로 사용하고 호가 미확인 경고 기록

### 지정가

완료 캔들에서만 판단한다.

- 롱: `low <= limitPrice`
- 숏: `high >= limitPrice`
- 캔들 시가가 지정가보다 유리하게 갭을 낸 경우 시가를 기준가격으로 사용하되 지정가보다 불리하게 체결하지 않는다.

### 스탑 시장가

완료 캔들이 트리거를 통과한 뒤 트리거 또는 갭 시가를 기준으로 불리한 슬리피지를 적용한다.

## 리스크 엔진 연결

모든 신규 모의주문은 실제 Phase 3 `calculateTradingRisk`를 호출한다. 서버는 클라이언트가 보낸 계좌 잔고·노출 값을 그대로 신뢰하지 않고 현재 모의 상태에서 다음 값을 다시 계산해 입력한다.

- account equity
- 일일·주간 실현손익
- 연속 손실 횟수
- 전체 노출
- 동일 방향 노출
- 공개 시장 데이터 상태 및 시각
- 공개 계약 규칙 상태 및 시각

리스크 엔진이 `allowed=false`이면 모의주문도 `rejected` 상태가 된다. 추천수량보다 큰 사용자 지정 수량, 동일 종목 중복 포지션·대기 주문, 증거금 부족도 별도로 차단한다.

## 손절·목표가·부분청산

- 완료 캔들에서 손절과 목표가가 동시에 도달하면 `stop_first`
- 목표가 1은 설정 비율만 부분청산
- 목표가 2는 잔여 수량 청산
- 수동 부분청산: 25%, 50%, 75%, 직접 수량
- 수동 전체청산: 잔여 수량 전체
- 거래소 유동성 부족에 따른 부분 체결은 모델링하지 않음

## 비용과 손익

각 체결에서 다음 값을 분리한다.

- 진입·종료 수수료
- 진입·종료 슬리피지
- 보유시간 비례 펀딩비
- gross PnL
- net PnL

대표 손익은 비용 차감 후 순손익이다. 공개 펀딩비 부호에 따라 양의 펀딩은 롱 지급·숏 수취로 계산한다. 실제 거래소 펀딩 지급 시각과의 정확한 정렬은 검증되지 않았으므로 보유시간 비례 추정이다.

## 계좌 계산

```text
equity = cashBalance + unrealizedPnl
availableMargin = equity - usedMargin
```

포지션 생성 전 필요 증거금과 진입 수수료가 사용 가능 증거금을 초과하는지 검사한다. 부분·전체청산 후 잔여 수량에 비례해 사용 증거금을 다시 계산한다. 레버리지를 높여도 리스크 엔진의 최대 허용손실은 증가하지 않는다.

## 로컬 저장

- 저장 키: `seungjae.paper-trading.v1`
- 스키마 버전: 1
- 주문 500개, 포지션 200개, 체결 1,000개, 거래일지 500개, event ID 500개 제한
- 손상 JSON 또는 잘못된 스키마는 저장 값을 삭제하고 새 상태로 복구
- API Key, Secret, Authorization, Token과 유사한 키가 포함된 데이터는 저장·가져오기 거부
- JSON 내보내기·가져오기 제공
- 전체 초기화는 별도 2단계 확인창 사용

현재 기록은 이 브라우저에만 저장되며 서버와 다른 기기에 동기화되지 않는다.

## 거래일지

자동 기록 필드:

- 거래·주문·포지션 ID
- 종목, 롱·숏, 주문 유형, 전략명
- 제출·체결·종료 시각
- 진입·손절·목표·종료 가격
- 최초·종료·잔여 수량
- 레버리지, 명목금액, 필요 증거금
- 진입·종료 수수료, 슬리피지, 펀딩비
- gross/net PnL, R multiple
- 최대 유리·불리 변동
- 종료 이유, 진입 데이터 상태, 시장 상태
- 경고, 규칙 위반 여부
- 일반 텍스트 메모

메모는 HTML로 렌더링하지 않으며 2,000자로 제한한다.

## 기초 통계

- 총 거래 수, 승률
- 평균 이익·손실, 기대값
- 평균 R, Profit Factor
- 최대 연속 승리·손실
- 누적 순손익
- 총 수수료·슬리피지·펀딩비
- 롱·숏, 종목, 시간대, 종료 이유별 성과

AI 복기와 사용자 전략 코드 실행은 포함하지 않는다.

## 테스트

Phase 6 신규 단위 테스트는 주문 상태, 시장가·지정가·스탑 체결, idempotency, 리스크 차단, 손절·목표가, 부분·전체청산, 비용, 증거금, 거래일지, 통계, 로컬 저장, 손상 복구, JSON 내보내기·가져오기를 검증한다.

API 스모크는 `paper-only`, `orderSubmitted=false`, `exchangeRequestSent=false`, 잘못된 입력, 요청 크기 제한, 내부 오류 일반화, 외부 거래소 요청 0회를 확인한다.

Playwright는 1440×900, 390×844, 360×740에서 모의주문, 대기 주문 취소, 부분·전체청산, 거래일지, 새로고침 복원, JSON 내보내기, 2단계 초기화, 차단 상태, 가로 스크롤 및 콘솔 오류를 검증한다.

## 제한사항과 미검증

- 실제 호가 깊이와 시장 충격
- 거래량 기반 부분 체결
- 실제 펀딩 지급 시각 정렬
- 다중 포지션·교차증거금의 거래소별 세부 청산 모델
- 서버·다른 기기 동기화
- 운영 환경 장시간 동시 사용자 부하
- 실제 모바일 소프트 키보드가 열린 상태의 viewport
- 실제 스크린리더 수동 감사

## 배포

Phase 6 작업에서는 운영 배포를 수행하지 않는다.
